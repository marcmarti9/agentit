# Launch / content system — reference-driven production

This playbook distills the useful parts of the bookmarked launch-library, AI-video, and faceless-video workflows into a reusable marketing/content procedure.

## Provenance

Reviewed 2026-08-25:

- https://x.com/askOkara/status/2090804619626860811 — launch-library reference workflow.
- https://x.com/motion_so/status/2083992227114520576 — product-context to scripted/voiced/rendered launch-video workflow.
- https://x.com/0xJokker/status/2091895032580112862 — faceless video pipeline using script/voice/timestamps/scene-aligned visuals/assembly.
- https://x.com/cyrilXBT/status/2083235395236495817 — repurposing and campaign prompt corpus, distilled rather than copied.

Role: product/creator workflow inspiration. Revenue estimates, agency-equivalence claims, or viral-performance anecdotes are not treated as verified outcomes.

## 1. Research comparable launches before choosing the creative

For a material launch, inspect several relevant launches rather than copying the first impressive post.

Study dimensions such as:

- opening hook;
- problem/frame;
- product reveal;
- proof/demo;
- visual asset type;
- CTA;
- founder/user voice;
- thread/reply structure;
- follow-up posts;
- distribution/channel adaptation.

Output a small pattern synthesis:

```text
patterns worth considering
patterns already overused
what fits this product/audience
what would be inauthentic here
original creative thesis
```

A high-performing launch is inspiration, not causal proof that its wording/format produced the result.

## 2. Build a factual launch brief

```text
product / feature:
audience:
problem / trigger:
one-sentence promise:
credible mechanism / differentiation:
proof actually available:
main objection:
primary CTA:
channels:
brand/rights/claim constraints:
reference patterns selected:
success metrics:
review window:
```

If `proof actually available` is empty, do not manufacture a metric/testimonial for the creative.

## 3. Scene plan before asset generation

For video or motion-heavy launch assets, decompose the script before generating dozens of assets.

```text
scene_id
start/end
spoken/on-screen claim
visual purpose
asset type/source
rights status
motion/edit note
verification needed
```

This creates a stable contract for voice, visuals, captions, screen recordings, generated imagery, and editing workers.

## 4. Production pipeline

```text
launch brief
-> script / story beats
-> claim check
-> voice / original audio
-> timestamps
-> scene plan
-> asset capture/generation
-> base assembly
-> captions/subtitles
-> brand + factual + rights QA
-> platform-native variants
-> publish
```

### Good automation targets

- transcription/timestamps;
- scene segmentation;
- candidate visual generation;
- asset naming/organization;
- captions/subtitles;
- crops/aspect-ratio variants;
- initial assembly;
- multiple cuts from one approved master;
- analytics collection/summarization.

### Keep judgment explicit

- final hook;
- claim accuracy;
- asset rights;
- brand fit;
- pacing;
- CTA;
- whether generated visuals feel generic or misleading;
- final publication decision.

## 5. Product URL is context, not a creative brief

Tools that can ingest a product URL and produce a launch video are useful accelerators. The URL does not automatically establish:

- audience priority;
- launch positioning;
- which claims are safe;
- what proof matters;
- desired tone;
- the best CTA;
- asset rights.

Feed the tool an approved brief/scene plan when the launch matters.

## 6. Repurpose the approved master intelligently

One strong launch artifact can become several native assets:

```text
master thesis / proof / demo
-> X post/thread
-> LinkedIn version
-> TikTok/Reels/Shorts cut
-> carousel
-> newsletter
-> landing-page section
-> follow-up FAQ/demo
```

Adapt opening, pacing and CTA to each channel. Do not mechanically duplicate identical copy everywhere.

## 7. Launch continues after day one

```text
wave 1
-> replies/questions/objections
-> clarification/demo/proof follow-ups
-> downstream metrics
-> hypothesis review
-> wave 2 / iterate / stop
```

Possible metrics:

- reach/views;
- watch/completion;
- saves/shares;
- profile/site clicks;
- qualified leads;
- signups;
- purchases/revenue;
- conversion rate;
- recurring objections/questions.

Choose the ones that correspond to the launch goal. Views alone do not make a launch commercially successful.

## 8. Persistent launch learnings

```text
observation:
supporting launches/posts + period:
confidence:
what we will change:
recheck after:
```

Do not generalize from one viral or one failed post.

## 9. Tool adoption test

Before building the workflow around Motion or another current AI-video tool, verify current availability/pricing/export/rights/integration details and test:

- first-draft quality;
- adherence to brief/scene plan;
- factuality;
- editability;
- time saved after corrections;
- voice/caption quality;
- asset/rights control;
- export/lock-in;
- cost per usable piece.

The relevant metric is closer to `quality-adjusted usable output / operator time` than “number of generated videos”.

## Distilled takeaway

```text
launch research
-> factual brief
-> scene/asset plan
-> automated mechanical production
-> human/agent judgment gate
-> platform-native distribution
-> outcome measurement
-> scoped learning
```

This preserves the leverage of the bookmarked workflows without turning Agentit into a content-farm machine.
