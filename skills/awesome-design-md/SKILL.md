# Awesome DESIGN.md reference scouting

Awesome DESIGN.md is a **reference library**, not an executable tool or a replacement for the project's own `DESIGN.md`. This Agentit-authored JIT skill links to the live library instead of copying its many brand documents.

## Procedure

1. First inspect the existing brief, brand rules, production styles, tokens and `DESIGN.md` (when relevant). Those sources remain authoritative.
2. Browse `https://github.com/VoltAgent/awesome-design-md/tree/main/design-md`. Open **one or two** relevant `design-md/<slug>/DESIGN.md` entries, not the entire collection. Examples: `stripe`, `vercel`, `ibm`, `figma`, `apple`, `linear.app`. Verify each entry exists before relying on it.
3. Extract the reusable design decisions actually needed: type hierarchy, spacing, semantic color roles, surface treatments, layout, animation and interaction. Treat entries as curated analyses rather than authoritative source-of-truth specs for the named companies.
4. Apply the lessons to the user's own product identity. Do not copy third-party logos, trademarks, trade dress or brand assets without permission, and do not replace client instructions with a borrowed theme.
5. If the resulting visual system becomes a durable project decision, use `design-md-workflow` to update the project's own `DESIGN.md`, after verifying its tokens against implementation.

Refresh the selected references from upstream on each new substantive design task. If access fails, disclose that freshness was not verified. Upstream main last checked on 2026-10-15 at commit `3b605329240ce735b510037cca322f1831fdd7f8`.
